# Chronomorph — three elastic clocks (Draft/HOLD)

Original C11 24 kHz mono composition engine. Three independently accumulated sixteenth-note clocks interact through alternating four-step master warp windows (lane 0 fixed, lane 1 ±warp, lane 2 opposite half-warp). Each lane has a 1–16-step editable pattern and a nested four-cycle pitch progression; seeded ghost hits and scale-degree mutation add controlled variation. Internal triangle bass, harmonic bell and noise/triangle dust voices provide standalone sound. No heap, queue or external dependencies in core; at most three ticks per sample, immediate stop/mute, resume preserves clock phase, reset initializes seed/preset and stops. Control and render calls must be serialized by consumer. No actual MIDI output or wire protocol. Host rate not an FM-1 hardware assumption.

## Live performance scenes

Four volatile scene slots capture BPM, warp, variation and all three pattern lengths/masks. Save a scene, change the pattern or temporal controls, then recall it during playback or pause. Recall uses the existing complete block control frame: no session reset, seed/preset change, transport event or device message. Slots persist in memory while the page is open; empty recall is disabled. Export scenes copies the four-slot bank into the JSON text area; save it externally or paste a previously exported bank and click Import scenes. The `chronomorph-scenes` version 1 document is capped at 2048 characters, accepts exactly four validated slots (including null), and replaces the bank atomically. Import does not apply a scene or change the current playback; explicitly recall a slot to apply it. Invalid versions, controls and oversized input leave the bank unchanged. No automatic storage, network or wire protocol is added. Intended CYDaux widget semantics are local scene capture/recall, not a new protocol. Browser qualification exercises actual HTTP scene frames, session/sequence continuity, nondecreasing clock ticks and paused recall. Core/target ABI unchanged.
